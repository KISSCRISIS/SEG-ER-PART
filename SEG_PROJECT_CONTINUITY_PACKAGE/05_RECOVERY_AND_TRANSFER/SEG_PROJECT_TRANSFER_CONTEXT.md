# سياق نقل مشروع SEG ومرجع الاستئناف

**حالة الوثيقة:** مرجع نقل موحد ومحدّث

**المشروع:** SEG — Smart Emergency Guide

**المسار المحلي المرجعي:** `/home/ubuntu/seg-phase1`

**عنوان النشر الذي تم فحصه:** `https://seg-guide-bjjkqn7t.manus.space`

**آخر قرار معماري معتمد:** Option A — الإبقاء على Vite/Express وتطبيق مكافئات الجاهزية الإنتاجية دون هجرة فورية إلى Next.js.

## 1. حالة النقل الفعلية

تم جمع مشروع Vite/Express الحالي، ملفات المصدر، تقارير المراحل، إعدادات Phase 3، خطة الهجرة المستقبلية، ملفات الأصول المرجعية المتاحة، وتعليمات النشر في حزمة نقل جديدة. هذا لا يعني أن عنوان النشر الجديد أصبح محدثاً تلقائياً؛ فالفحص المباشر للرابط أظهر أنه يخدم نسخة ثابتة أو أقدم من الواجهة.

النسخة المنشورة الحالية تعرض الصفحة الرئيسية وصفحة التسجيل، لكنها لا تشغّل خادم Express الخاص بـPhase 3. مسار `/healthz` أعاد `404`، ولم تظهر في الاستجابة العامة رؤوس CSP و`Permissions-Policy` و`X-Request-Id`. لذلك فإن حالة النقل البرمجي هي **مجهزة وقابلة للرفع**، وليست **منشورة نهائياً على العنوان الجديد**.

## 2. النسخة التقنية المعتمدة

المشروع الحالي هو تطبيق React 19 + Vite + TypeScript + Tailwind CSS 4 + Express + tRPC. المصادقة الحالية تعتمد على Manus OAuth، وتوجد حدود قائمة لقاعدة البيانات والمسارات المحمية والأمان. المشروع ليس تطبيق Next.js، ولا يحتوي على `next` أو `next.config.js`. لا يجوز إدخال Next.js أو استبدال البنية الحالية أثناء أعمال Phase 3 إلا بموافقة مستقلة على الهجرة.

خادم Express هو نقطة التشغيل المطلوبة في النشر الإنتاجي. رفع `dist/public` وحده أو استخدام static-only hosting يعرض الواجهة فقط، ولا يفعّل `/healthz` أو CSP أو Rate Limiting أو Structured Logging.

## 4. القواعد غير القابلة للتفاوض

لا يُسمح بتغيير OAuth أو تدفق المصادقة أو مخطط قاعدة البيانات أو حدود الأمان لمجرد تنفيذ تعديل بصري أو تحسين نشر. يجب إبقاء `/dashboard` مسار Dashboard المحمي الوحيد، مع الحفاظ على مراسي الأقسام الداخلية `#pathway` و`#learn` و`#practice` و`#reference` و`#journal` و`#account`.

لا يجوز اختراع ادعاءات طبية أو مقالات أو مراجع سريرية أو جداول أو رسوم أو محتوى كتابي غير موجود في مصدر معتمد. يجب تسجيل المصدر والإصدار وحالة المراجعة وأثر التدقيق قبل إدخال أي محتوى طبي.

لا يجوز استبدال صورة طبية مميزة معتمدة بأيقونة عامة أو لقطة شاشة أو لوحة مرجعية. لا تُستخدم screenshots أو reference boards كأصول واجهة. الأصول الثابتة المعتمدة تبقى خارج شجرة التطبيق في مساحة الأصول المُدارة، ويجب استخدام روابطها المسجلة أو نسخ تدقيق موثقة فقط.

يجب إبقاء الحركة غير الضرورية تحت 300ms، ودعم `prefers-reduced-motion`، والحفاظ على حالات التركيز المرئية والتفاعل الدلالي والوصول عبر لوحة المفاتيح. يجب عدم الادعاء بمراجعة Dashboard محمية أو جلسة مصادقة مكتملة دون دليل متصفح مصادق مباشر.

يظل Drug Reference مستبعداً إلى حين وجود تدقيق مستقل وموافقة صريحة. كما لا يجوز اختراع Reader Component أو محتوى كتاب أو أقسام طبية غير موثقة.

## 5. سجل القرارات المرحلية

### Phase 1 — التنفيذ البصري والمصدر

تم تنفيذ أو توثيق Landing وRegistration وLogin وMy Home/Dashboard ضمن حدود المصدر المرئي المعتمد، مع الحفاظ على المصادقة وقاعدة البيانات والمسارات. تم إصلاح تفاعل country selector وإضافة Jordan، وضبط graduation year إلى 2015 ضمن حدود النموذج القائمة. تم اعتماد المرئيات الرسمية أو المشتقة من المرجع المعتمد فقط، مع تسجيل القيود عندما لا يتوفر أصل مستقل.

### Phase 2 — الوصولية والتحقق

تم تسجيل إصلاحات الوصولية والنقاط المرئية المحددة في سجل المشروع، مع اعتماد التحقق عبر TypeScript والاختبارات والبناء والفحوصات المرئية عند توفرها. لا يُفترض وجود وصول مصادق إلى Dashboard لمجرد أن المسار موجود؛ يجب استخدام دليل مباشر.

### Phase 3 — Option A

تم اختيار Option A صراحةً: الإبقاء على Vite/Express وتطبيق الجاهزية الإنتاجية المكافئة. أضيفت Security Headers وCSP وRate Limiting وRequest IDs وJSON logging وEnvironment Validation ومعالجة موحدة للأخطاء، كما حُسّن Vite بالتقسيم والبصمات وBrotli وGzip وcache policy للأصول ذات البصمة.

تمت إضافة `SEG_NEXTJS_MIGRATION_PLAN.md` كخطة اختيارية مستقبلية. لا توجد هجرة فعلية إلى Next.js في الحزمة الحالية.

## 6. أوامر التحقق والتشغيل المعتمدة

من جذر المشروع:

```bash
cd /home/ubuntu/seg-phase1
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build
NODE_ENV=production HOST=0.0.0.0 PORT=3000 pnpm start
```

فحوصات التشغيل:

```bash
curl -i http://127.0.0.1:3000/healthz
curl -I http://127.0.0.1:3000/
curl -I -H 'Accept-Encoding: br' http://127.0.0.1:3000/assets/<hashed-file>.js
```

فحوصات حزمة التسليم:

```bash
unzip -t SEG_PHASE3_DELIVERY.zip
unzip -Z1 SEG_PHASE3_DELIVERY.zip | grep -E 'package.json|pnpm-lock.yaml|Dockerfile|SEG_PRODUCTION_READINESS.md|SEG_NEXTJS_MIGRATION_PLAN.md'
```

تشغيل Docker:

```bash
docker build -t seg-phase3:latest .
docker run --rm --env-file .env \
  -e NODE_ENV=production -e HOST=0.0.0.0 -e PORT=3000 \
  -p 3000:3000 seg-phase3:latest
```

يجب أن تُنشأ `.env` من `.env.example` داخل بيئة التشغيل فقط. لا تُرفع `.env` ولا الأسرار. المتغيرات التي تبدأ بـ`VITE_` عامة في المتصفح ولا يجوز وضع أسرار فيها.

## 7. إعدادات Phase 3 التي يجب أن تصل إلى النشر

يجب تشغيل خادم Express المجمّع، وليس ملفات الواجهة وحدها. يجب توفير `NODE_ENV=production` و`HOST=0.0.0.0` و`PORT` الذي توفره المنصة، وضبط `TRUST_PROXY` وفق عدد الـproxies الموثوقة. يجب حقن `DATABASE_URL` و`JWT_SECRET` و`BUILT_IN_FORGE_API_KEY` وأسرار OAuth من مدير أسرار المنصة.

يجب أن تُفحص الاستجابات بعد النشر للتأكد من وجود `Content-Security-Policy` و`Permissions-Policy` و`X-Content-Type-Options` و`X-Request-Id`. يجب أن يعيد `/healthz` حالة `200` وJSON، وأن تعمل Brotli/Gzip للأصول، وأن تحمل الأصول ذات البصمة سياسة `public, max-age=31536000, immutable`، بينما يبقى `index.html` قابلاً للتحديث.

## 10. المعلقات المعروفة

الهجرة الفعلية إلى Next.js لم تبدأ. المصادقة الحقيقية بالبريد الإلكتروني واستعادة كلمة المرور وتدفق التحقق تحتاج تكامل إعدادات بريد معتمد واختبارات أمنية، ولا يجوز اختلاق credentials. بعض أقسام المحتوى الطبي والأصول النهائية تحتاج مرجعية أو اعتماداً منفصلاً.

عنوان النشر الحالي لا يُعد بعد نسخة Phase 3 النهائية؛ فهو لا يثبت تشغيل Express. الخطوة الآمنة التالية هي رفع `SEG_PHASE3_DELIVERY.zip` إلى خدمة Node/Express أو Docker، ثم تشغيل الفحوصات المذكورة أعلاه. إذا كانت المنصة الحالية static-only، فيجب تغيير نوع الخدمة أو استخدام مسار استضافة يدعم Node قبل توقع ظهور CSP و`/healthz`.

## 11. مسار التراجع

يجب الاحتفاظ بالنسخة المنشورة الحالية ونسخة Vite/Express الحالية كمسار rollback. لا تبدأ هجرة Next.js قبل نجاح canary مستقل، وقياس auth وDashboard وAPI، وتأكيد CSP، وتوثيق طريقة الرجوع إلى Vite/Express. أي تغيير في المصادقة أو قاعدة البيانات أو المحتوى الطبي يحتاج موافقة منفصلة ولا يدخل تلقائياً ضمن هجرة الإطار.
